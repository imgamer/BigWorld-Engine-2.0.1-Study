# BigWorld Engine 2.0.1 架构总览

> 仓库版本：BigWorld Technology 2.0.1（BigWorld Pty, Ltd.）
> 仓库定位：面向 MMORPG 大型多人在线游戏的“客户端 + 分布式服务端 + 工具链”一体化引擎。
> 文档目标：从代码模块与功能模块两条主线，全面剖析 BigWorld 引擎的源码结构、关键抽象、运行时数据流与跨模块协作。

---

## 1. 引擎定位与核心思想

BigWorld 是一套**面向超大规模持久状态世界**的商用 MMO 引擎。它在架构层面有几个鲜明的特征：

1. **以“实体 (Entity) 为中心”**：玩家、NPC、道具、投射物、可交互对象都抽象为 Entity。Entity 拥有声明式定义（`entities.xml` + `.def`）、跨进程的属性同步、方法调用、AOI（Area of Interest）可见性。
2. **服务端微内核 + 多进程分布式**：服务端不是一个单体进程，而是由若干“角色进程”协作：
   - `cellapp`（cell 模拟进程，按空间网格划分负载）
   - `baseapp`（玩家 base 实体 + 持久代理）
   - `baseappmgr` / `cellappmgr`（管理进程，做负载均衡与分配）
   - `loginapp`（登录入口）
   - `dbmgr`（数据库总控）
   - `reviver`（崩溃恢复）
   - `machined`（机器守护，二进制托管）
3. **客户端瘦协议 + Python 脚本**：客户端只持有“可见的” Entity，绝大部分游戏逻辑由服务端 Python 驱动，客户端用 Python + C++ 模块组合表达表现层。
4. **空间分块 (Chunk) + 几何映射 (GeometryMapping)**：世界不是一张大地图，而是被切成网格化 chunk，按需流式加载，支持室内外 portal 连通。
5. **Mercury 网络层**：自研 UDP 可靠传输 + 接口描述（IDL）+ bundle/channel 模型，所有跨进程通信走 Mercury。

```

                       +--------+--------+
                                │ loginOK (含 baseapp 地址)
                                ▼
                       +-----------------+
                       |   baseappmgr    |  ← 选址、负载均衡
                       +--------+--------+
                                │ 分配
                                ▼
   Client  ──── udp ───►  +-----------------+  ◄── backup ──►  +-----------------+
                          |   baseapp #N    |                  |  baseapp #N+1   |
                          +--------+--------+                  +-----------------+
                                   │
                                   │ entity 进 cell 时
                                   ▼
                          +-----------------+
                          |   cellappmgr    |  ← 选址、负载均衡
                          +--------+--------+
                                   │
                                   ▼
   +-----------------+     +-----------------+     +-----------------+
   |  cellapp #1     |◄───►|  cellapp #2     |◄───►|  cellapp #3     |   ← cell 间 ghost / 迁移
   +-----------------+     +-----------------+     +-----------------+
                                   │
                                   ▼
                          +-----------------+
                          |     dbmgr       |  ← 持久化 + billing
                          +--------+--------+
                                   │
                                   ▼
                          +-----------------+
                          |   MySQL / XML   |
                          +-----------------+

   全程：machined 守护所有进程（启停、健康检查、watcher 转发）
        reviver 监听死亡事件，触发备份切换
```

## 5. 关键抽象与跨模块协作

### 5.1 Entity 跨进程模型

一个逻辑 Entity 在 BigWorld 中由 1~3 个“部分 (portion)”组成：

- **Base portion**（baseapp）：长期存在、可与 DB 持久化、客户端 mailbox 直连
- **Cell portion**（cellapp）：物理存在、AOI 可见、参与空间模拟
- **Client portion**（客户端）：表现层

每个 portion 的属性/方法/属性变化可见域由 `.def` 文件中的 `BASE_DATA` / `CELL_DATA` / `CLIENT_DATA` / `ONLY_OTHER_CLIENT_DATA` / `ONLY_PERSISTENT_DATA` 标志控制（见 `EntityDescription::DataDomain`）。

跨进程调用通过 **Mailbox**（`MailBoxBase` / `RemoteEntityMethod`）做远程方法分发，由 `entitydef` 库序列化。

### 5.2 Chunk ↔ Entity 协作

- 服务端 `cellapp` 在 `ServerChunkSpace` 上跑空间模拟；`Entity` 通过 `EntityRangeListNode` 加入 `Cell` 的 `RangeList`，驱动 AOI。
- 客户端 `ClientChunkSpace` 按 `ChunkManager::camera()` 流式加载 chunk，把可见的 chunk item（模型/地形/光源/粒子）放到 `moo::RenderContext` 渲染。
- 玩家进入某 chunk 时，cellapp 把对应 cell 的可见 Entity 的 client portion 通过 baseapp 推给客户端。

### 5.3 Mercury 跨层调用

- `network` 库定义 `InterfaceTable` / `InterfaceElement`（IDL），生成 `*_interface.hpp/cpp`（如 `BaseAppInterface`、`CellAppInterface`、`DBMgrInterface`、`ClientInterface`）。
- `bundle` 是消息聚合单元，`channel` 提供可靠有序语义。
- `EventDispatcher` 是所有进程的主循环心脏，驱使 timer、network、frequent task、main loop task。

### 5.4 资源系统

- `BWResource::instance()` 是入口，挂载 `MultiFileSystem`（可叠加 zip / 目录 / cache / 网络包）。
- 资源以 `DataSection` 抽象呈现：XML、二进制 packed、zip 内嵌、目录树都能统一读写。
- `entitydef` 用 `DataSection` 解析 `entities.xml`；`chunk` 用它解析 `.chunk` 文件头；`moo` 用它读 `.visual` / `.primitive` / `.mfm`。

### 5.5 Python 脚本贯穿全栈

- 客户端、baseapp、cellapp、dbmgr 都嵌入了 CPython（`pyscript` 库 + `python/`）。
- Entity 的方法实现、Controller 行为、UI 行为大多写在 Python；C++ 通过 `PyObjectPlus` / `ScriptObject` 暴露。
- `ScriptedModule`（客户端）与 `PythonServer`（服务端）承担脚本入口。

## 8. 版本与已知限制

- 当前仓库为 **BigWorld 2.0.1** 源码，含 VS2005/2008 工程文件 + Linux Makefile + Xbox 360 工程（部分）。
- 部分依赖（SpeedTree、Scaleform、FMOD、Umbra、Mozilla）以**预编译 lib**形式给出（见 `lib/`），其源码不在本仓库。
- `machined` 守护进程源码不在本仓库，但其协议（`machine_guard.hpp`）和客户端封装（`machined_utils`）可用。
- 文档（`doc/`）为 Doxygen 自动生成的 HTML/CHM，可作为类层级与依赖图的补充参考。
